# 学习通扫码确认后不跳转 · 0.1.4

记录日期：2026-11-04。此修复不代表三平台真实课程验收完成。

## 现象与证据

- 用户截图显示扫码已经识别，用户确认在手机学习通点过确认，桌面仍停留在确认页面。
- 本机应用记录出现导航拦截通知；只读核对通知，没有读取 Cookie、密码、登录令牌或身份资料。
- 无登录会话访问官方公开登录页时，其默认 `refer` 指向 HTTP 的个人空间。官方页面的扫码成功分支按该返回地址跳转；应用 HTTPS-only 策略会阻止该地址。
- 同一官方入口显式传入 HTTPS 个人空间地址后，公开页面保留这个返回地址。实际 Electron 读取结果记录在 `reports/public-entry-smoke.json` 的 `chaoxingHttpsReturn` 布尔字段；不记录页面、二维码内容或认证响应。

## 修复范围

应用的学习通登录入口现在固定传入 `https://i.chaoxing.com/` 作为 `refer`，沿用账号的原会话分区。没有修改官方网页逻辑、伪造登录状态、读取凭据、放开 HTTP、扩大域名名单或关闭安全机制。

单元测试检查显式返回地址和 HTTPS 限制；桌面夹具检查返回地址能够正常导航，原来的 HTTP 地址及外站地址仍被拦截。夹具不是扫码实测。

为了不干扰用户已经添加的账号，打包检查新增本地启动时可选的专用临时校验目录。只有 UUID 标识被接受；没有任意目录输入、界面高权限接口或生产模拟模式。脚本先核对隔离目录再写测试数据，平常启动和原会话不变。

## 用户复测

1. 从托盘完全退出旧版，打开 0.1.4；保留原账号，不退出平台或删除账号。
2. 账号管理中对原账号选择“打开登录”，以便使用更新后的登录入口；仅刷新旧地址不一定使用新入口。
3. 自行扫码，在手机学习通确认登录。开发者不代为操作认证。
4. 核对能否跳转至个人页面；再点学习通网页自己的“课程”进入“我学的课”。小房子只打开个人空间，不保证直接显示网课目录。
5. 如果仍失败，报告页面是否跳转、是否出现拦截通知或再次要求登录；不要发送完整鉴权网址、二维码、密码或验证码。

2026-11-04 用户确认“已通过扫码登录进去了”，本机运行版本核对为 0.1.4。本次账号的扫码登录已获得用户人工确认；没有由此认定登录持久化或其他账号兼容。真实目录、连续两章、完成状态、异常与两小时稳定性仍需独立验收。

后续在“我学的课”页面复现 0.1.4 目录读取失败，与扫码返回问题分开处理。0.1.5 开发修复见 `学习通课程读取修复.md`；不要为此删除账号或重复扫码。

## 2026-11-05：首次扫码仍不稳定

0.1.5 第一候选中，用户反馈第一次扫码并确认后没有跳转，第二次重新扫码才进入。已观察到登录后的个人空间和真实课程卡片；这不能认定为单次扫码稳定通过。提醒记录包含导航被拦截，但当时通知没有记录协议和错误类型，无法据此断言这次仍是同一个 HTTP 返回原因。

第二候选在学习通登录页上方增加“手机已确认，核对登录”，由用户点击后在同一账号会话打开固定 HTTPS 个人空间。它只提供核对入口，不代用户确认、不设置登录状态，也不保证认证一定已完成。HTTP 跳转和其他名单外跳转分别给出提示；主页面加载失败只显示数值错误代码，不记录完整网址或凭据。非登录页隐藏该按钮。

合成回归覆盖按钮到固定个人空间的正常跳转、离开登录页后隐藏按钮，以及 HTTP / 外站仍被阻止。2026-11-05 用户按只扫码一次的复测要求操作，反馈“点‘核对登录’后进入”；随后观察到已登录的个人空间和目录，并成功导入 20 门课程。已确认“一次扫码 + 手动核对”的可用路径，不能认定扫码自动跳转通过。

第二候选首次启动仍要求用户登录，因此关闭后会话保持未通过；不要求为此次课程读取重复扫码。后续课程入口加载失败时也出现 HTTP 拦截通知，但没有记录完整目标或重定向链，不能把课程入口故障直接归因为扫码返回，更不能据此放开 HTTP。当前不宣称扫码问题完全修复。
