## 官方未登录入口检查（2026-11-03）

使用实际 Electron 页面访问，不是本地网页夹具。证据为 `reports/public-entry-smoke.json`，仅反映测试时网络与页面状态，不代表用户已登录或课程可用。

| 平台 | 公开入口观察 | 与实课验收的区别 |
|---|---|---|
| 学习通 | 官方登录页可显示，检测为未登录 | 尚未输入账号、验证登录或读取目录 |
| 中国大学 MOOC | 官方首页可显示且有登录入口，状态仍为未知 | 尚未打开认证弹层或登录，不能当作登录成功 |
| 智慧树 | 官方直接登录页可显示，检测为未登录 | 尚未输入账号、验证共享课目录或播放器 |

0.1.2 的智慧树旧入口在转到新登录域名时触发主文档 ERR_ABORTED（-3）。0.1.3 改为观察到的官方直接入口，消除此入口误报；仍保留原 `zhihuishu.com` 名单与加载失败处理，不关闭安全机制、不泛化忽略 ERR_ABORTED。

## 尚未排除的兼容性风险

- 学校自定义单点登录或第三方认证域名不在受控名单内。
- 异步页面、嵌套框架、受保护播放器、非标准 HTML 视频或特殊课程目录。
- 平台不允许后台播放、需要用户点击播放或限制章节解锁。
- 候选选择器与真实页面不匹配；平台升级后结构改变。
- 链接带访问凭据时会拒绝本地保存，需核实可安全使用的规范课程地址。
- 平台标记延迟出现，或找不到与当前章节可靠关联的完成状态，此时保持“待确认”。

不会通过关闭浏览器安全、伪装页面可见、注入完成请求或绕过验证来解决兼容问题。

## 待执行的逐平台验收单

每个平台分别复制一份记录，不能用一个平台的结果代替另外两个。

- 平台 / 课程范围 / 测试时间：待填写（不要记录学号、账号、Cookie、完整鉴权 URL）。
- [ ] 在应用内原始网页完成真实登录，关闭后仍保持会话。
- [ ] 只读取自己的课程；目录和顺序与平台可见页面一致。
- [ ] 读取当前课程章节，不误读另一个账号或另一门课程。
- [ ] 播放第一个可进入视频；正常速度、无额外完成请求。
- [ ] 观察结束并可靠核对当前章节身份。
- [ ] 第二个章节允许进入时才切换并播放。
- [ ] 分别记录本地 ended 和平台完成标记，未确认不能标成完成。
- [ ] 验证验证码 / 登录失效 / 人工题目 / 未解锁时暂停。
- [ ] 同平台双账号删除或退出互不影响；同平台始终一任务。
- [ ] 休眠 / 唤醒 / 重启 / 断网 / 托盘恢复后正确核对。
- [ ] 三个平台一起连续运行两小时，保留无敏感数据的资源和状态记录。

失败记录必须包含“现象、页面结构差异、保守处理、是否可安全修复”，不得填成成功。

## 学习通扫码返回修复（2026-11-04）

用户确认手机已点确认，应用出现导航拦截通知。官方公开登录页默认返回 HTTP，显式 refer 参数可保持 HTTPS 课程入口。0.1.4 固定该 HTTPS 返回，不扩大域名名单、不允许 HTTP。新入口真实加载与受控导航回归通过；没有代用户扫码或认证，登录后目录和实课仍未验收。详见 `学习通扫码登录修复.md`。

## 发布后人工复测确认（2026-11-04）

- 用户原话：“已通过扫码登录进去了”。这是用户在本机操作后的反馈，不是自动化测试结论；没有代用户认证或读取登录凭据。
- 只读核对正在运行的应用包版本为 0.1.4；本地元数据为 1 个账号、0 门课程、0 个任务。数量不构成登录证明，只表明课程导入尚无本地记录。
- 后续已进入平台“课程 → 我学的课”，复现 0.1.4 目录读取失败。下一步是用修复版重新核对导入，不能在旧版反复刷新，也不能把扫码成功推广为课程适配成功、重启仍登录或双账号隔离通过。
- 本节为发布后的验收跟踪；既有 v0.1.4 标签和 Release 附件保持不变。

已验证的是旧版失败和新规则的合成测试，不是新版真实导入成功。真实导入、章节和播放仍待用户本机复测；详见 `学习通课程读取修复.md`。
