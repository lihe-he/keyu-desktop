# 学习通个人课程读取修复

记录日期：2026-11-05。保留 2026-11-04 历史复现；0.1.5 为尚未发布的开发修复。

## 现象与入口

用户已自行扫码并确认登录成功，初次看到的是个人空间周课表。原工作台小房子按钮标为“打开我的课程入口”，实际上只返回个人空间首页，造成误导。

在平台自身菜单选择“课程”，出现“我学的课 / 我教的课”和课程封面后，再点助手的“我的课程 → 刷新所选账号”，0.1.4 仍提示未可靠识别到个人课程。已观察到真实目录并复现失败；不是用户忘记确认扫码，也不是需要重新添加账号。

## 结构差异与修复

- 课程列表位于平台允许域名中的嵌套页面，容器使用 `id="courseList"`，旧规则只有同名 class，没有匹配该 ID。
- 课程标题链接路径为 `/mooc-ans/visit/stucoursemiddle`，旧课程地址模式未包含它。
- 新增容器内 heading 标题链接的规则，避免封面重复链接、教师信息和“课程已结束”遮罩被当成课程名。
- 平台停止开课不等于学生学习完成；结束遮罩不会产生完成标记。
- 不把 iframe 上下文地址保存为课程链接，不采集密码、Cookie、访问令牌；测试仅使用重新构造的假数据。
- 小房子改名“打开学习通个人空间”；失败提示直接说明从平台“课程”进入“我学的课”，周课表不是网课目录。
- 生产导航、HTTPS 和页面安全策略不变。开发夹具只允许精确的测试 iframe 域名，用于验证已有跨域框架读取能力，不放宽生产页面限制。

## 验证边界

新增单元测试覆盖标题提取、去重、同名不同课程、结束标识、周课表排除、个人课程上下文、登录页和隐藏元素。桌面回归使用明确标注的跨域 iframe 假页面，检查导入的课程地址属于 iframe 所在域、没有导入上下文参数或教师名，同时保留三平台播放 / 隔离 / 恢复测试。

2026-11-04 第一套规则有 135 项单元、5 项桌面流程、122563ms 合成三通道运行通过的历史记录。2026-11-05 第二候选为 151 项单元、6 项桌面流程通过；免安装构建在隔离目录中的启动检查和三个官方未登录入口检查通过。合成短时耐久仍是 11 月 4 日旧候选结果，没有在第二候选重跑，不能算作当前构建耐久证据。

**合成测试通过不代表真实适配通过。** 第二候选已实机导入课程，见下文；章节及两个可进入视频仍未验证。无需为继续读取课程重扫、卸载现有安装或清理日常会话。

## 第四候选：限定课程入口的 HTTPS 重试

对上述固定入口做无登录凭据的公开检查，HTTPS GET 返回 302、TLS 校验通过；HEAD 返回 405 并声明允许 GET。这只证明 HTTPS 端点可响应，不证明已登录课程可打开。

第四候选先阻止 HTTP，在同一账号会话以原参数尝试一次 HTTPS。触发条件限定为当前加载的 v24 签名目录入口、主页面服务端重定向、精确站点与路径；用户名、密码、非默认端口、片段或其他入口一律不触发。HTTPS 再跳回 HTTP 就停止，不循环、不打开 HTTP、不改变完成状态。临时参数只在该次加载内使用，加载结束后释放；普通课程加载错误不再附带登录核对建议。

新增合成回归验证 HTTPS 单次重试可正常读取测试章节、循环重定向只尝试一次、不适用的跳转仍阻止，以及数据库和通知不含临时签名。真实章节与播放结果必须另行记录。

第四候选已完成 170 项单元、9 项桌面流程、打包启动和三个官方未登录入口检查。免安装程序位于 `release/candidate-0.1.5-r4/win-unpacked`。第三候选正常保存退出后已启动第四候选，尚未核对其真实登录或课程打开结果。用户要求先提交 Git 并暂停，后续从第四候选实机复测继续，不将此状态记为验收通过。
